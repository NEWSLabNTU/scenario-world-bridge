# 071: The towns' crosswalks have no regulatory elements

**Severity**: low. `autoware_lanelet2_map_validator` reports every crosswalk lanelet (its
`mapping.crosswalk.missing_regulatory_elements` check); driving does not need the elements. **Status**:
open, unassigned (swb 133, 2026-11-20), for the next revision of `jerry73204/carla-town-autoware-maps`.
**Found**: 2026-11-20, swb 241 and 243, validating issue 068's Town03 candidate.

## What happens

No town map has a crosswalk regulatory element:

| map | crosswalk lanelets | crosswalk regulatory elements |
|---|---|---|
| Town01, Town02 (v2026.11b) | 0 | 0 |
| Town03 (v2026.11b) | 72 | 0 |
| Town05 (v2026.11b) | 66 | 0 |
| Town10 (v2026.11b) | 16 | 0 |
| Town03, regenerated by `carla_map_gen` (068's candidate) | 73 | 0 |

The validator counts one error per crosswalk lanelet. In 068's candidate it is the only check
left (73 errors). Neither the source pack nor crdesigner writes the elements, and none of
`carla_map_gen`'s 14 repairs adds them.

Autoware 1.5's crosswalk module finds the crosswalks on the path through the routing graph
(`getCrosswalksOnPath`). Without an element it stops `stop_distance_from_crosswalk` (3.5 m) before
the crosswalk. An element would add explicit stop lines (`ref_line`) and a polygon.

## Fix (proposed)

A 15th repair in acb's `carla_map_gen.repairs`. It adds one crosswalk regulatory element per
crosswalk lanelet (`refers` the lanelet) and a test, about 40 lines. It would clear 73 errors in
Town03, 66 in Town05 and 16 in Town10, and change nothing else in the maps.

To check before it lands: whether an element without a `ref_line` makes Autoware take the
element's (absent) stop line over its 3.5 m rule. A drive over a crosswalk on Town05 or Town10,
with a pedestrian, before and after, shows it. Adding the crossing road lanelets' stop lines as
`ref_line` is the fuller version, if the module needs them.
